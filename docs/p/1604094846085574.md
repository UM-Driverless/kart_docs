# Kart Medulla PCB v2

**Design ID:** `1604 0948 4608 5574`

The Kart Medulla is the kart's interface board: an ESP32-S3 microcontroller sitting between the
Orin compute module and the vehicle's sensors and actuators, breaking out to screw terminals
CN1–CN10. This page is revision **v2** of that design.

## What this number is

A **design ID** names a design revision, not an individual board. Every board built to this
revision carries the same silkscreened number and resolves here. It is a part number, not a serial
number — nothing on this page distinguishes one physical board from another.

The QR on the board holds only these 16 digits: no domain, no organisation name, no URL. That is
what makes the marking permanent, because renaming a GitHub organisation, letting a domain lapse or
moving hosting cannot invalidate a number that refers to none of them. Resolution happens through
the [scanner page](../scan.md), which navigates relative to itself.

## Where the design lives

The KiCad project is at
[`projects/kart-medulla/`](https://github.com/UM-Driverless/dv-hardware/tree/main/projects/kart-medulla)
in the `dv-hardware` repository. That repository is the authority for the board itself — schematic,
layout, requirements and per-board rework. The firmware that runs on it is
[UM-Driverless/kart-medulla](https://github.com/UM-Driverless/kart-medulla). For how the board wires
into the rest of the kart, see [Kart Medulla](../assembly/electronics/kart-medulla/index.md).

## Fabrication record

**Not yet fabricated.** No board exists with this design ID. The `fab/` directory in `dv-hardware`
is empty, and the fabrication files under `projects/kart-medulla/fabrication/` are the ones that
produced the earlier board described below.

When boards to this revision are ordered, record here:

| Field | Value |
|---|---|
| Gerber-export commit | *(the `dv-hardware` commit the gerbers were exported from — not the last commit that touched the schematic; only the export is what a fab house received)* |
| Fabrication date | |
| Quantity | |
| Paired firmware | *(the `kart-medulla` and `kart-brain` commits that target this hardware)* |

The commit hash belongs on this page rather than on the board, because a commit cannot contain its
own hash: silkscreening a hash would change the file being hashed. The board therefore carries this
stable design ID, and the exact source state it was built from is recorded here, where it can also
be corrected.

## Rework

None — no board of this revision exists yet.

Rework is per physical board, so it cannot be described by a design ID at all. Where two boards of
this revision diverge because one was patched, that difference is recorded in `dv-hardware` against
the individual board, not here.

## The board that exists today

The kart currently runs an **earlier** board, fabricated before design IDs existed, so it has no
silkscreened ID and no page here. It is identified by its gerber-export commit `84d6dd0` and is
paired with `kart-brain` at `c200e56`. It carries known faults — notably the CN10.2 brake output
sitting on the wrong side of the LM358, so it delivers the unamplified 0–5 V DAC output where the
valve needs 0–10 V. Its full rework list is in
[`projects/kart-medulla/README.md`](https://github.com/UM-Driverless/dv-hardware/blob/main/projects/kart-medulla/README.md).

That board is **v1**: it is the first version, and a version number is just a name. The revision on
this page is **v2** rather than v1.1, because it changes the board in ways that are not compatible
with the old one — a whole new number, not a decimal. Version numbers here mark incompatibility, so
they say something a reader can act on: a v2 board and v1 firmware are not interchangeable.

The version is printed on the board as `kart-medulla-v2` and appears in the git tag and the
`fab/<board>/<rev>/` folder, following the project's `<board>-v<N>` convention. It is separate from
the design ID above, which is random and carries no version meaning.
